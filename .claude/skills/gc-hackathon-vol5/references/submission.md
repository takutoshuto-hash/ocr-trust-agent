# 提出物と提出方法

一次情報: https://zenn.dev/hackathons/google-cloud-japan-ai-hackathon-vol5

## 提出の締め切り（確定）

**2026年10月15日（木）23:59**。この日時までに参加登録とプロジェクトの提出の両方を完了することで正式な参加となる。

- チームメンバーの追加・脱退も締切まで可能（プロジェクト提出後も、締切までは変更できる）

## 提出方法: Zennのハッカソンダッシュボード（確定）

提出は、Zenn内のハッカソンダッシュボードから**プロジェクトを提出**することで行う。外部フォームは使わない。流れは次のとおり。

1. **エントリー**: 公式ページの「エントリー」から参加規約に同意してエントリーする
2. **参加者情報の入力**: エントリー後のダッシュボードから、参加者情報（氏名・所属など）をGoogleフォームで入力する。入力が完了したらダッシュボードの「次へ」で進む
3. **プロジェクトの作成 または チームへの参加**:
   - 個人またはチームリーダーの場合: 「プロジェクトを新規作成」からプロジェクトを作る
   - チームメンバーとして参加する場合: 自分のZennユーザー名をチームリーダーに伝え、リーダーがプロジェクトのチーム管理からユーザー名で招待する。届いた招待をダッシュボードで承認するとメンバーになる
4. **プロジェクト情報の入力**: プロジェクトの編集ページで、下記の「提出するプロジェクト情報」を入力する
5. **提出**: 提出タブから内容を確認のうえ提出する。提出期限を過ぎるとプロジェクトの編集・提出はできなくなる

ダッシュボード: https://zenn.dev/hackathons/google-cloud-japan-ai-hackathon-vol5/dashboard

## 提出物の要件（確定）

ダッシュボードで作成したプロジェクトに以下を登録して提出する。

1. **プロジェクトのGitHubリポジトリの連携**（ダッシュボードからGitHub Appをインストールして連携する。リポジトリは公開・非公開を問わない）
2. **プロジェクトをデプロイしたURL**（Google Cloudへのデプロイが必要。ローカル環境のみは不可。dev環境でも動作確認できれば可）
3. **プロジェクトの説明**
   - プロジェクトが対象とするユーザー像と課題、課題へのソリューションと特徴をまとめた説明文
   - システムアーキテクチャ図の画像
   - プロジェクトの動作を説明する**3分程度のデモ動画**（自作のうえYouTubeに公開し、URLをプロジェクトに登録する）

あわせて以下の条件を満たすこと。

- 指定のGoogle Cloud AI製品およびアプリケーション関連製品を用いること（[regulations.md](regulations.md) 参照）
- 開発者が自己の権利で使用できるツールを使用すること
- **日本語で記載すること**
- 参加者が独自に制作したものであり、第三者の権利を侵害しないこと
- オープンソースソフトウェアを使用する場合、ライセンス条件を遵守し、提出物においてライセンス情報を明記すること
- **ハッカソン開始時点で一定進捗していた既存プロジェクトの提出は、公平性の観点から控えること**（期間中に開発したものを提出する）

補足:

- **Zenn記事の投稿は任意**。投稿する場合はカテゴリ「Idea」で公開し、URLをプロジェクトに登録する
- プロジェクトコードは可能な範囲の公開でよいが、どの部分を開発したか・パッケージ化している部分はどこかなどの構成説明を必ず加え、主要機能がモックではなく実装されていることが分かる程度に公開する

## 提出物の公開範囲（確定）

- 提出締切後、提出済みプロジェクトのページ（説明・アーキテクチャ図・デモ動画など）が**一般公開される**
- **連携されたGitHubリポジトリとデプロイしたURLは審査にのみ使用され、プロジェクトページには公開されない**

## GitHubリポジトリ・デプロイの維持と提出後の扱い（確定）

1. GitHubリポジトリは公開・非公開を問わない。**提出時点の状態を2026年12月1日まで保ち、期間中はリポジトリの連携解除や削除を行わない**こと
2. **審査は連携リポジトリのデフォルトブランチを対象とする**。提出後も開発を継続したい場合は別のブランチで行い、デフォルトブランチは提出時点の状態を保つこと
3. 審査期間である**2026年12月1日までの間は、デプロイした上で動作確認できる状態**にしておくこと
4. 提出時点の成果物を評価するため、**提出後のコンテンツ（リポジトリ・動画など）の修正は控える**こと
